# 05 · 峰谷闸（贵的时段只收不发）

## 规则

```
峰时 = 工作日 09:00–12:00、14:00–18:00（北京时间，不含法定节假日）
其余 = 谷时（午休、18 点到次日 9 点、周末、法定节假日全天）
```

- **谷时**：分身正常说话
- **峰时**：只收不发
- 例外可配：主人在说话 / 同一个人连 @ N 次（模板默认关掉例外，纯「只收不发」）

## 实现要点

1. **唤醒控制和发送控制是两件事，都要卡。**

   - 把闸放在 `scheduleWakeV2` 只能挡住「新唤醒」，挡不住「已经在跑的回合拖到峰时才发」，
     也挡不住其他插件直接调用发送。
   - 如果目标是**省推理费**：控制模型调用入口（唤醒 + 定时 + 主动机会都走同一道闸）。
   - 如果目标是**峰时静默**：发送出口也要再查一次时间。
   - 明确三种情形各自的规则：已开始的回合、预告通知、主人消息，分别放行还是拦截。

2. **节假日要名单，且要过期检测**：按放假通知写日期，跨年补一次。
   调休上班日不算峰时——规则说的是「周一至周五」。
   模板里的节假日数组只是**不完整示例**，不能当全年日历用；正式部署要放完整年度区间，
   并在日期过期（已到下一自然年）时打日志提醒。
3. **判定用固定时区**：`Asia/Shanghai`，不要用本机时区。

## 这是用户自定义的时间策略

「峰价」「谷价」这个名字可以叫任何收费/静默规则。这里不绑定任何具体收费标准，
先把它当作**用户自定义的时段策略**：在哪些时段禁止新唤醒、在哪些时段允许发送。

## 通知

到点往群里发图：

| 时机 | 发什么 |
|---|---|
| 峰价开始 | 一张「高峰时段」的图 |
| 谷价开始 | 一张「空闲时段」的图（不提前预告） |
| 峰价前 10 分钟 | 一句文字预告 |

图放 `assets/peak.png`、`assets/offpeak.png`，换图直接覆盖，不改代码。

## 顺带：主动机会也要压

除了「回消息」，桥还会定时判断「要不要主动冒个泡」。峰价时这个也要压，
不然省下的钱又从主动发言漏出去。
