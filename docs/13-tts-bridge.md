# 13 · 朗读桥（TTS）

让助手说话，最容易踩的坑不是模型，是**浏览器**：TTS 要么花钱调云端接口，要么用你已经在网页端登录的账号。
朗读桥选后者——**声音走你自己的浏览器**，DSH 只负责把要念的字递过去。

## 两半，缺一不可

```
DSH 会话 ──▶ 宿主插件（dsh-tts-bridge） ──▶ 本机 HTTP 队列 ──▶ 浏览器扩展 ──▶ chat.deepseek.com 念出来
                     ↑ 选「听哪个会话」                                                    │
                     └──────────────────── 回执 / 停止 / 哪条念完了 ──────────────────────┘
```

- **宿主插件**：盯住选中的会话，一「轮」说完才把整段排进队列；管收藏、最近念过的、听谁的
- **浏览器扩展**：轮询取件 → 把文字输进网页对话框 → 等它复述完 → 点网页自己的「朗读」按钮 → 回报执

不直接把文字丢给网页的「朗读」是有原因的：网页只会念**它自己刚生成的那条回复**，所以扩展得先让它复述一遍再点朗读。

## 本机小门：为什么需要它

桌面宿主会给每个插件的 HTTP 路由套一层「浏览器访问」闸，普通浏览器客户端拿不到宿主令牌 → `/state`、`/next` 全 403。
可插件**自己 listen 的端口**不归那道闸管。于是插件在这个端口上再开一扇小门：

- 只 listen `127.0.0.1`
- **只认扩展来源**，网页（`http(s)`、`null`）连读都读不到
- 除 `/where` 外都要带**每次启动新发**的令牌（只在内存里，不写日志不落盘）
- 只放行扩展真会用的那几条路径

`/where` 是引导：扩展还不知道宿主在哪个端口、令牌是什么，先问这一下；它只回给本机 + 扩展来源。

### 一条差点让人查一整晚的坑

扩展来源白名单最初只写了 `chrome-extension://`。**火狐的扩展来源是 `moz-extension://`** ——
于是火狐版问路直接被 403（「这个口只给浏览器扩展用」），拿不到令牌，后面全 403，
界面上的表现却是「**扩展在跑、一直没在听任何会话**」。

```
允许：chrome-extension://  moz-extension://  safari-web-extension://
拒绝：http://  https://  null
```

排查要点：**先看浏览器控制台里那几条 403 的 URL**，再对照小门的来源白名单——比猜令牌、猜端口快得多。

## 浏览器扩展移植（Chrome → Firefox）

同一份源码翻一份，比另抄一份好维护：

| 位置 | Chrome MV3 | Firefox MV3 |
|---|---|---|
| 后台 | `background.service_worker` | `background.scripts: [find.js, bg.js]`（事件页，没有 Service Worker） |
| 加载依赖 | `importScripts('find.js')` | 去掉，由清单按顺序加载 |
| 扩展 API | `chrome.*`（Promise 只在部分版本可用） | 统一走 `browser.*`，别名兜底：`const api = browser ?? chrome` |
| 清单 | 无 | `browser_specific_settings.gecko`：id、`strict_min_version`、`data_collection_permissions` |

`data_collection_permissions`（火狐 140 起强制）填 `{ required: ["none"] }` —— 这类扩展只连本机，不收集数据。

## 分发与签名

- **临时载入**（`about:debugging` → 临时载入附加组件）：不签名，改代码方便，重启浏览器失效
- **常驻安装**：正式版只认 Mozilla 签名的包 → 走 AMO「未列出（unlisted）」通道，Mozilla 签、不公开上架

```bash
npx web-ext sign --source-dir extension --channel unlisted \
  --api-key <JWT issuer> --api-secret <JWT secret>
```

凭据放在仓库外的状态目录，别提交进 git。每改一次代码要 **把版本号 +1** 再签（同一版本号 AMO 只收一次）。

> **商标**：扩展名字里不能出现 Mozilla / Firefox，否则 AMO 会以
> `Add-on names cannot contain the Mozilla or Firefox trademarks` 打回。叫「朗读桥 · 火狐版」就行。

## 常见故障

| 现象 | 先查 |
|---|---|
| 左下角「没在听任何会话」 | 是不是小门 403（来源白名单）／扩展有没有取到件（`/state` 里的 `lastNext` 有没有在跳） |
| 取到件但不出声，回执「点了朗读但没出声」 | 浏览器只认**真人手势**：先在网页里手动点一次它的「朗读」，之后自动才生效 |
| 宿主重启后一直 403 | 令牌是每次启动新发的；扩展要重问路换新令牌，别拿着旧的死磕 |
| 换端口就全断 | 端口不能写死；用「问路」发现，或从已打开的 DSH 页面地址里抠 |

## 设计取舍

- **声音不进 DSH**：DSH 只发文字，音频由网页端播；换机器、换账号都只影响浏览器那一半
- **整轮才念**：一条条念会把半句话念出去；以「一轮结束」为界，长回复也完整
- **失败要能看见**：状态行直接写原因（「朗读桥报错：…」），别让用户对着「没在听」猜
