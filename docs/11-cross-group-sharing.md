# 11 · 跨群共享（授权投影）

群与群之间默认**不共享**。想共享时不取消隔离，而是在隔离之上加一层「经过批准的投影」。

## 为什么不能直接用 public

`public` 表示**公共事实**（比如「这个插件是 MIT」）。
而「群 A 里某人说他在修机器人」是**某个群发生过的经历**，两者不能混：

- 混用会让摘要模型有机会把「群里的私事」升级成「公共事实」；
- 一旦成了 public，所有群都能读，等于绕过授权。

## 流程

```
群 A 原记录（group:A）
   ↓ 需要共享时
生成共享摘要（新的一条，带来源）
   ↓ 明确指定
允许读取的群：B、C（不是「所有群」）
   ↓
群 B 检索时能看到它；群 D 看不到
   ↓ 原记录被纠正 / 删除
共享摘要同步更新 / 撤回
```

四步要落实：

1. **原记录不动**，仍在 `group:<原群号>`。
2. **共享摘要单独存**，带 `source`（指向原记录）和 `sharedWith`（群列表）。
3. **共享要显式授权**：指定允许读取的群，默认不开放。
4. **撤回要传播**：原记录删改，摘要跟着更新或撤掉；索引也一起。

## 一个例子

> 群 A 原记录：某群友讨论机器人故障，里面有私有地址和日志。
> 允许共享的摘要：该群友近期正在修复机器人。

群 B 只读到第二条。**同一人同时在两个群，本身不构成跨群转述授权。**

## 实现建议

- 同一个数据库可以承载：`scope` 之外再加 `sharedWith` 字段，检索时 `本群 ∪ sharedWith(本群)`。
- 分享动作只允许由主会话（私聊）发起；群分身的「想分享」只能作为**提案**，不是直接发布。
- 共享摘要要记「谁批准的、什么时候、原始来源是哪条」，便于撤销。

## 验收

见 `docs/09-validation.md` 的「跨群共享」项：
摘要不升级权限、未授权群读不到、原记录删除后摘要同步撤回。
