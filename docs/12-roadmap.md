> 不按日期排，按依赖排；估计用「人日」量级，不是承诺。

## 第一阶段：记忆分类与保留（当前重点）

**目标**：让「留什么、忘什么」有规则可依，且不误删。

要做：

1. 记忆写入时带类型（事件 / 印象 / 日记 / 钉 / 资料）——现在靠约定，下一步进 schema。
2. 30 天压缩：普通群事件 → 一句摘要，原文可清；**约定、纠错依据、钉、日记不动**。
3. 体检清单接进流程：每两周出一次，人工过一遍再执行（脚本已有）。
4. 摘要与索引跟原记录同生共死。

验收：`docs/09-validation.md` 第 11、13 项。

风险：压缩掉的东西回不来。所以先只出清单，不自动删。

## 第二阶段：受控跨群共享

**目标**：群与群之间不取消隔离，加一层授权投影。

要做：

1. 记忆记录加 `sharedWith`（允许读取的群列表），默认空。
2. 生成共享摘要：带来源、带授权群、由主会话发起。
3. 检索时 `本群 ∪ sharedWith(本群)`。
4. 撤回传播：原记录删改 → 摘要与索引同步更新或撤掉。
5. 群分身的「想分享」只能成为提案，不能直接发布。

验收：第 12、15 项。

风险：一旦开口，撤回传播没做全，就会出现「删了还看得见」。

## 第三阶段：人格更新与外包整理

**目标**：人格变化可追踪、可回滚；重活交给便宜模型。

要做：

1. 人格修改提案：来源（哪条记忆）、理由、改哪个字段、幅度。
2. 检查层：来源是否主人身份、字段是否在允许范围、改动是否过大。
3. 版本记录 + 一键回滚。
4. 整理器做成可替换的模型接口：本地先跑通，再把「哪些内容可以外发」单独配置。

验收：第 16 项。

风险：人格漂移和隐私外流。所以先做版本与回滚，再谈外包。

## 明确不做的

- 不做「自动删记忆」：删除必须有人看过清单。
- 不做「分身可写本体」：即使 Agent 变强，这条不松。
- 不做「为了架构好看提前拆地基」：双记忆系统在没做投影前，先按会话用一套，
  不双写、不宣称已统一。

## 排期方式

- 每个阶段开工前，先补该阶段的验收项（先写测试再写实现）。
- 阶段结束打一个 release（`scripts/release.ps1`），kit 包里带上本文件。
- 阶段之间允许插入「当前最痛」的小修，但不动上面的顺序：**先稳，再广，再强**。
