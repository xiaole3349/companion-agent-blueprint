# 10 · 备份、恢复与回滚

## 该备份什么

| 内容 | 位置（示例） | 频率 |
|---|---|---|
| 人格 | 底色代码 + `persona.txt` | 每次改动前 |
| 记忆 | `fish-memory/` + 中央库 `memory.sqlite3` | 每日 + 整理前 |
| 配置 | 桥、记忆、心情、钉、图书馆 | 每次改动前 |
| 状态 | 会话映射、唤醒配置、峰谷状态 | 每日 |
| 脚本与插件 | `scripts/`、`kit/`、外挂包 | 版本化进 git |

## 恢复顺序

1. **先恢复配置**（桥、记忆服务、白名单），确认能启动、能连。
2. **再恢复人格**，确认说出来的「还是她」。
3. **最后恢复记忆**，确认召回不串 scope、不丢钉。
4. 每步之间做一次冒烟：发一条消息看回不回、回得对不对。

## 回滚原则

- 任何「改配置 / 改库 / 删文件」之前先留带时间戳的备份，改完说清哪份是哪份。
- 回滚 = 用备份覆盖当前，再重启对应进程；不要手工「反向改一半」。
- 记忆库回滚前先停记忆服务，避免回滚过程中又被写入。

## 迁移失败怎么办

- 迁移用「先读源库、写新库、跑重复检测」的只读方式，别直接改写源库。
- 中途失败：源库保持原样，新库丢弃重建；不要「半迁移」硬上线。
- 迁移完成后保留源库 N 天（默认 30），确认新库正常再删。
