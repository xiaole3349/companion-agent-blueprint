# 02 · 人格怎么叠

## 两层：底色 + 正文

| 层 | 放在哪 | 谁改 | 作用 |
|---|---|---|---|
| 性格底色 | 插件代码里的常量 | 只有主人（需要改代码） | 定死的行为倾向，比如「自主性优先」 |
| 人格正文 | `persona.txt` | 可以放宽给本人 | 称呼、口癖、示例、边界细节 |

两段在装配时拼起来：`底色 → --- → 正文 → 安全尾巴`。

**为什么把底色放进代码**：文本文件放久了会被「顺手改一下」改掉；代码里的常量要动就得改代码，动作更显眼、也会进版本记录。这不是绝对锁（同账号同权限总能改），但是一层有摩擦的锁。

## 正文要懒加载，不要启动时读一次

```js
// 每轮装配时 stat 一次，mtime 变了才重新读
const 人格路径 = new URL('./persona.txt', import.meta.url)
let 缓存 = { mtime: 0, 全文: '' }
function 读人格() {
  const st = statSync(人格路径)
  if (st.mtimeMs !== 缓存.mtime) 缓存 = { mtime: st.mtimeMs, 全文: readFileSync(人格路径, 'utf8') }
  return 缓存.全文
}
```

`systemPrompt.section({ text })` 的 `text` 可以给函数，DSH 每次装配都会调用它。
这一条省掉「改完要重启」的整条链路——模板里强烈建议这么做。

## 长度预算

- 底色 + 正文建议 ≤ 12000 字符（超了会挤掉工具说明的注意力）
- 超预算时**降级到只带底色**，不要整段不注入：宁可人格少一点，也别让它失忆式回答

## 分身的「群聊版」卡

群里的分身和桌面是同一个本体，但说话节奏不同。做法是给分身一张单独的角色卡：

- 只写「群里怎么说话、怎么分分寸」
- 人设（名字、自称、关系）一律写「以共享人格段为准」，不要在卡里重写一遍
- 重写 = 两套规则打架 = 人格漂移

## 改人格的流程

1. 备份 `persona.txt`（带时间戳）
2. 改，存 UTF-8 无 BOM
3. 不用重启，下一轮生效（前提是懒加载）
4. 长度检查：`persona.txt` 字符数 + 底色长度 ≤ 12000

## 人格修改提案（独立的第五段流程）

「记录经历」和「修改人格」是两件事，不能合并。私聊里聊到的东西先成为记忆，
**不是**直接写进人格。

```
私聊事件 → 记忆
   ↓
主会话提出人格修改提案（改什么、为什么、依据哪条记忆）
   ↓
检查：来源是否为本人身份、字段是否在允许范围、变更幅度是否过大
   ↓
留版本 + 理由，可回滚
   ↓
共享人格更新 → 所有窗口下一轮读同一版
```

### 哪些可以自主改

| 字段 | 允许自主改 | 需要确认 |
|---|---|---|
| 称呼偏好、口头习惯、相处默契 | ✅ | |
| 生活细节、兴趣爱好 | ✅ | |
| 性格倾向、关系定性 | | ✅ |
| 边界规则、权限相关 | | ✅（且不能靠人格扩大权限） |
| 名字、形态、核心设定 | | ✅（改的是「她是谁」） |

### 三条不可越过的线

1. **人格修改不能扩大工具权限**：写进人格的「我可以自己发消息」不会让权限真的变大。
2. **人格修改不能覆盖用户的撤销/停止指令**。
3. **来源要可信**：外部资料即使经由私聊进来，也不能自动成为修改指令。

### 回滚

- 每次改动留一份带时间戳的备份 + 一句理由
- 回滚 = 用备份覆盖 + 重启（或等懒加载下一轮）
- 版本记录里要能看出「谁、何时、为什么」
